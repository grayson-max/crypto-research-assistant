# Mini AI Crypto Research Assistant — Project Summary

**Author:** Grayson Hoe
**Context:** Summer internship project, Fort Point/Lakeside (Registered Investment Advisory)

## Purpose

An internal-use pipeline that generates a short daily research brief on BTC,
ETH, and SOL for an advisor's review. It is a research-support tool only —
it does not place trades, does not interact with client accounts or
custodians, and does not give investment advice directly to any client.

## Data Sources

| Source | Used for | Notes |
|---|---|---|
| [CoinGecko](https://www.coingecko.com/) `/coins/markets` API | Price, 24h/7d/30d % change, market cap + rank, volume, supply, ATH distance, 7-day sparkline for BTC/ETH/SOL | Free tier, no API key required |
| [NewsAPI](https://newsapi.org/) `/v2/everything` | Recent headlines mentioning Bitcoin/Ethereum/Solana | Free tier (100 req/day); originally scoped for CryptoPanic, but CryptoPanic discontinued its free API tier in April 2026 — see Limitations |
| [Anthropic API](https://www.anthropic.com/) (`claude-opus-4-8`) | Drafting the written brief from the structured data | Given market data + tagged headlines as input; does not have independent internet access or knowledge of prices beyond what it's given |

All API keys are stored in a local `.env` file, excluded from version control via `.gitignore`, and never hardcoded in source files.

## Pipeline Design

The project is a modular Python script pipeline rather than a single Jupyter
notebook. Each stage is an independent, individually testable module, and
`main.py` orchestrates them in sequence:

```
fetch_market_data.py  →  price / 24h change / market cap (CoinGecko)
fetch_headlines.py    →  recent headlines per coin (NewsAPI)
sentiment.py           →  keyword-based positive/neutral/negative tagging
generate_brief.py     →  builds the prompt, calls Claude, appends disclaimer
main.py                →  runs the above, saves to reports/brief_YYYY-MM-DD.md
```

This structure was chosen over a notebook because it's easier to maintain
and re-run on different days, and because it sets up cleanly for scheduled
automation without any restructuring.

**Automation:** a daily 8:00 AM cron job runs the pipeline automatically. A
secondary `launchd` agent checks every 30 minutes whether that day's report
already exists, and runs the pipeline if it's missing — this catches days
where the laptop was asleep at 8am, generating the brief within roughly 30
minutes of the laptop next being woken. A native macOS notification fires
when a brief finishes generating.

## AI Summarization Approach

The brief is generated by a single call to Claude (`claude-opus-4-8`), given:

1. The structured market data (price, 24h change, market cap per coin)
2. The list of recent headlines per coin, each tagged with a sentiment label

The system prompt instructs the model to:
- Avoid the words "buy," "sell," and "should"
- Avoid price predictions or targets
- Describe what the data and headlines show, rather than recommend action
- Write in short bullet points throughout, not paragraphs — one fact per
  bullet, terse data-label formatting for stats (e.g. "Market cap: $1.30T
  (#1 rank)"), so the reader can scan line by line

**The compliance disclaimer is not left to the model.** It is a fixed string
appended to every generated brief in code, after the API call returns —
this guarantees the disclaimer is present even if a given model response
were to omit it.

Sentiment tagging (positive/neutral/negative) happens *before* the LLM call,
using simple keyword matching rather than an LLM judgment call. This keeps
sentiment tagging transparent and auditable — for any headline, you can
point to exactly which word(s) triggered its label, which matters more in a
compliance-sensitive setting than a marginally more nuanced but opaque
method.

## Key Limitations

- **Headline relevance noise.** NewsAPI searches full article text, not just
  headlines, so a coin can be "matched" from a passing mention even when
  the headline isn't substantively about that coin. A purpose-built crypto
  news aggregator (the original CryptoPanic plan) would likely reduce this,
  but its free tier was discontinued mid-project.
- **Sentiment tagging is intentionally simple.** Keyword counting has no
  understanding of negation, sarcasm, or context — a headline like "fears
  of a crash prove unfounded" could mis-tag as negative. The tradeoff is
  deliberate: transparency over sophistication for this compliance context.
  Most real-world headlines observed during testing tagged as `neutral`,
  which reflects that day-to-day crypto reporting is often matter-of-fact
  rather than clearly loaded language — this is expected behavior, not a bug.
- **No backtesting or accuracy validation.** The brief's accuracy depends
  entirely on the quality of the two upstream data sources at request
  time. `verify_brief.py` does cross-check every `$`/`%` figure the AI
  writes against the fetched market data (and, failing that, against the
  day's headlines, inserting a source citation if it matches one) — this
  catches wrong numbers, but not other kinds of AI-drafted prose
  inaccuracy (e.g. a technically-true-but-misleading characterization),
  which remains unverified beyond the compliance-language checks in the
  prompt.
- **Model instruction-following is a prompt constraint, not a hard
  guarantee.** The "no buy/sell/should" rule is enforced via the system
  prompt, not a code-level filter. Testing has consistently shown Claude
  respecting this instruction, but a periodic manual spot-check of
  generated briefs is recommended.
- **Live data only.** The pipeline has no historical backfill — it can only
  report on current market conditions at the moment it runs, not past dates.

## Fit Within a Regulated RIA Workflow

- **No execution authority.** The pipeline only reads public market data and
  generates text. It has no connection to any brokerage, custodian, or
  trading system, and cannot place, modify, or cancel any order.
- **No client-identifying data.** All data sources are public market
  data and public news; no client account information, holdings, or
  personal data passes through the pipeline at any point.
- **Advisor oversight is required by design.** Every generated brief is
  explicitly labeled research-only and is intended for the advisor's
  internal review — not for direct client distribution — until reviewed.
- **Disclaimers are structurally guaranteed**, not just prompted for: the
  compliance disclaimer is appended in code after every generation, and the
  system prompt separately constrains the model's language.
- **Auditability.** Every brief is saved as a dated file, and sentiment
  tags are traceable to specific keywords — both support after-the-fact
  review of how a given brief's language was arrived at.
